# Website QA — 5 September 2026

Scope: local frontend and Django backend, including tenant/account authentication,
authority scopes, staff/student routes, enrollment writes, audit/report filters,
calendar/attendance, and cohort graduation. Browser checks use synthetic data;
this is not a live deployment, load, or third-party infrastructure penetration test.

## Confirmed and fixed

| Finding | Correction | Regression coverage |
|---|---|---|
| Enrollment errors could include another program's student roll numbers | Resolve student, semester and class IDs through the caller's authority scope before validation; use generic program mismatch messages | Cross-program guessed IDs for single and bulk enrollment, no disclosure and no writes |
| Inactive/archived roles continued granting permissions | Only active, unarchived roles contribute permissions and signed-in role lists | Disabled/archived role denied; reactivation restores access |
| Duplicate IDs in one bulk enrollment request failed rather than safely skipping duplicates | Deduplicate student IDs; lock the target semester/class during bulk creation | Duplicate IDs, retries, row counts and audit attribution |
| Impossible dates crashed audit and attendance-report filters | Validate impossible dates and reject reversed audit ranges with 400 | Invalid day/month and reversed-range requests |
| Batch graduation changed students without student audit snapshots; undo could reverse separately graduated students | Record explicit internal batch-action provenance and audited bulk updates; undo only changes those students | Same-day individual graduate preserved; cohort graduate corrected; profile edits preserve provenance; history actor and reason |
| Expired access cookies prevented valid refresh sessions from reopening the workspace | Validate with the refresh session; never mount protected content using an unvalidated persisted profile | Access renewal, no premature protected render, permission-denied route |
| Temporary refresh/network failure discarded an otherwise valid session; invalid login triggered global logout | Retry transient validation failures and leave credential errors on the login flow | Retry and invalid-login browser scenarios |
| Late responses/refreshes could cross an account switch | Bind protected requests to their originating session; reject stale results; clear server cache on fresh profile | Delayed response and delayed refresh after switching accounts; logout cache reset |

## Verification

- Backend regression cases: `tests/test_qa_regressions.py` and graduation tests in
  `tests/test_academics_api.py`; run the complete pytest suite for existing tenant,
  authority, student portal, accounts, audit, attendance and assessment coverage.
- Frontend: build, lint and formatting checks, plus `npm run test:session`.
  The browser regression command requires Node 22+ and Chrome; set `CHROME_BIN`
  if Chrome is not at the platform default. It uses a separate local origin,
  synthetic accounts, and mocked API responses, with no real college data.
- Existing bilingual-calendar browser QA covered both date systems, holiday
  labels, recorded dates, month/year navigation and mobile width.

## Migration and deployment

Review `students.0009_track_batch_graduation`, which adds an internal
`graduated_by_batch` flag to live/history student rows and constrains it to
GRADUATED students. It is not an editable or returned student API field.

Existing graduates receive `false`: earlier cohort actions cannot be reliably
identified from the previous date-only tracking. Undo preserves these students;
review/correct legacy statuses individually when needed. No speculative backfill
or change to existing student statuses is performed.

The earlier pending `performance.0009_attendancesession_makeup_reason_and_more`
also remains in the migration graph. Neither migration was applied to a college
database during QA; use the normal backup and tenant migration deployment process.
